# Обнаруженные баги и их влияние на структуру тестов

В ходе написания автотестов (POST и PATCH запросы) было обнаружено, что некоторые автотесты иногда падают, в зависимости от используемых тестовых данных. В ходе анализа конкретных случаев, были выявлены следующие дефекты:

1. Различие в поведении валидаторов при обработке POST и PATCH запросов
   * При создании фильма и передаче туда несуществующего поля со значением, вернется 400, но при передаче несуществующего поля в PATCH-запрос, возвращается 404 (фильм не найден), хотя в по логике и документации сваггера должно возвращаться 400.
   * Имя фильма не должно быть пустым, однако через PATCH можно его изменить на такое, если в базе нет фильма с пустым названием, при этом POST-запрос отработает ошибку и вернет 400.
   * Через POST-запрос можно создать фильм с негативной стоимостью, через PATCH - нет.
   * Целый ряд полей различно обрабатывается в случае ввода в них null (None), а именно - name, location, description, price, published, GenreId. Эти поля со значением null вызовут 400 при POST-запросах, но 404 при PATCH-запросах.
   * При изменении названия фильма посредством PATCH-запроса на уже существующее, также возвращается 404, а не 400. Поэтому в генерации фильма добавлено добавление двух больих случайных чисел для избежания создания уже существующего имени.

2. Наличие этой проблемы привело к конфликтам в тестах при попадании в них различных тестовых данных, которые должны вызывать 400. Я оставил константу с только теми неправильными данными, которые обрабатываются корректно (вызывают 400).
3. В файле constants есть закомментированная константа FILM_KEYS_MUTATIONS, которая переопределит текущую и позволить обнаружить найденные дефекты в валидации при многократном запуске тестов.

# Настройка .env файла

Для корректной работы тестов, работающих под сессией админа, необходимо настроить .env файл и ввести туда админские креды.
1. Создать в корне проекта файл .env
2. Заполнить его настоящими данными админа по аналогии с примером в файле .env.example
